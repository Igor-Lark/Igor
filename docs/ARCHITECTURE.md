# Архитектура

## Решение по стеку

Репозиторий содержал только заголовок README, переиспользовать было нечего.

Сравнивались три рабочих варианта:

- Python и FastAPI удобны для фоновых задач, но интерфейс пришлось бы собирать вторым приложением.
- Next.js на serverless плохо держит долгие задачи: процесс запроса не должен быть их хозяином.
- Один долгоживущий процесс Node.js с Next.js, SQLite и своим исполнителем задач закрывает интерфейс, хранение и параллельные задачи без отдельной инфраструктуры.

Выбран третий вариант. Параллельность ограничена числом задач и отдельным пределом внешних HTTP-вызовов. Этого достаточно для одного локального пользователя и не требует Redis.

## Поток данных

```
boat-sochi.ru
  └── направления услуг
        └── страницы
              └── независимые задачи
                    └── отчёты, версии, источники, согласования
```

Общие заметки сайта доступны всем направлениям. Факты, отчёты и реклама хранятся со ссылкой на направление. Страницу чужого направления к задаче привязать нельзя. Источник можно явно связать с несколькими направлениями.

Задачи не стоят в одном общем конвейере. У типа свой обработчик: получение страницы, исследование, текст, SEO, объявления, промпт, разбор креатива.

## Исполнитель задач

`src/server/jobs/runner.ts` раз в секунду забирает задачи со статусом «в очереди». Запланированная задача становится очередью, когда наступает её время.

Статусы разделяют техническое выполнение и решение человека. Успешный обработчик ставит «ожидает проверки» или «завершена». «Согласована» появляется только после решения пользователя.

Ошибка и отмена одной задачи не меняют остальные. После перезапуска задача, которая была «выполняется», становится «прервана» и сама не запускается: повтор делает человек, потому что внешние вызовы нельзя безопасно проигрывать молча.

Пауза и отмена выставляют флаг, обработчик проверяет его между шагами. Уже записанные источники и версии не удаляются.

## Получение страниц и внешние источники

Это разные модули.

- Снимки сайта принимают только `boat-sochi.ru` и его поддомены.
- Исследование ходит по публичным адресам, которые указал пользователь или вернул поиск.
- Перед соединением имя разрешается в адреса. Внутренние, петлевые, канальные и служебные адреса отклоняются. Соединение закрепляется за уже проверенным адресом.
- Каждый редирект проверяется заново.
- `file:`, логин в URL и числовые адреса запрещены.

Если страницу или источники получить не удалось, отчёт с выдуманными фактами не создаётся. Фрагменты сохраняются только когда ответ реально прочитан. Без языковой модели исследование может сохранить фрагменты, но прямо пишет, что выводы не составлялись.

## Модель и поиск

`src/server/llm/client.ts` — единственная точка вызова языковой модели. Ошибки, тайм-аут и повтор при 429/5xx обрабатываются там. Ответ, который ссылается на адрес вне полученного списка, в факты не попадает.

Поиск вынесен в `src/server/research/search.ts`. Сейчас это Tavily. Другой поставщик подключается той же функцией `search`.

Цены в предложенном тексте сравниваются с исходными материалами. Неизвестная цена остаётся видимой и помечается предупреждением, а не подменяется округлением.

Разбор снимка для SEO — правила по полученному HTML. Частотность и позиции не вычисляются. Комментарий модели, если ключ есть, хранится отдельно и не считается фактом.

Оценки креатива 1–10 появляются только из модели со зрением. Без неё сохраняются размер, тип и вес файла.

## Данные

Файл `data/boat-content-factory.sqlite`. Снимки HTML и оригиналы изображений лежат рядом, в базе хранится относительный путь. Имена файлов — идентификаторы, не имена от пользователя.

Схема в `migrations/001_init.sql`. Основные сущности: сайт, направление, страница, снимок, задача, событие задачи, источник, отчёт, наблюдение, версия текста, SEO-разбор, рекламная концепция, версия объявления, промпт, креатив, разбор креатива, событие согласования, журнал.

Новая версия текста после правки человека не наследует согласование предыдущей.

## Каталоги

```
src/app            интерфейс и маршруты API
src/server/db      база, миграции, стартовые данные
src/server/jobs    очередь и обработчики
src/server/http    политика адресов и загрузка
src/server/llm     языковая модель
src/server/services согласования и создание сущностей
src/components     формы
migrations         SQL-миграции
tests              сценарии приёмки
```

Интерфейс читает базу на сервере. Изменения идут через небольшие POST-маршруты. Долгие операции не блокируют страницу: список обновляется, пока задача в очереди или выполняется.

## Риски

- Сайт на Tilda может отдать мало текста, если блок собран скриптом. Снимок тогда помечается неполным, и недостающий текст не анализируется.
- Формулировки цен на главной и в `llms.txt` расходятся. Обе сохранены как неподтверждённые, приложение само одну не выбирает.
- Лимиты длины объявлений Директа указаны как ориентир: кабинет их меняет.
- Пока процесс один, второй экземпляр на том же файле SQLite лучше не запускать.
