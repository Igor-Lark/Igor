# Как выпустить токен API Директа для агентов РК

Не пароль. Не Client secret приложения. Нужен **OAuth-токен**, выданный под **vitaminki21**.

Токен **не писать в чат**, не класть в git, не снимать скрин с ним в переписку.  
Яндекс **не показывает** старый токен повторно. Сохрани его сразу в секрет Cursor.

Официально два этапа: [регистрация приложения](https://yandex.ru/dev/direct/doc/ru/concepts/register) и [ручной токен](https://yandex.ru/dev/id/doc/ru/tokens/debug-token).

---

## Этап 0. Браузер

1. Открой чистое окно (лучше инкогнито).
2. Выйди из всех Яндексов.
3. Войди **только** как **vitaminki21** (тот же логин, что кабинет Директа boat-sochi).
4. Проверь: https://direct.yandex.ru — видны РК **704503370** (Сириус) и другие живые (GP **713449981**, RB **713632237**). **712465896 («Морские прогулки») больше нет — это нормально.** Если чужой кабинет — не тот аккаунт.

---

## Этап 1. Приложение в Яндекс ID

1. Открой https://oauth.yandex.ru/?dialog=create-client-entry  
   или https://oauth.yandex.ru/ → **Создать приложение**.
2. Тип: **Для доступа к API или отладки**.
3. Заполни:
   - **Название:** `boat-sochi-rk-agents` (любое своё).
   - **Почта:** та, что на этом Яндексе.
   - **Доступ к данным:** начни писать `директ` → выбери **Использование API Яндекс Директа (`direct:api`)**.
   - Организацию (`passport:business`) не добавляй, если не заходишь в Директ от имени организации.
4. Платформа / Redirect URI (если спрашивает):  
   `https://oauth.yandex.ru/verification_code`
5. **Создать приложение**.
6. На странице появятся **ClientID** и **Client secret**.
   - ClientID — длинная строка, понадобится в ссылке и в заявке.
   - Client secret — **это не токен API**. В чат не слать. Можно сохранить у себя в менеджере паролей.

Список приложений потом: https://oauth.yandex.ru/

---

## Этап 2. Заявка на доступ к API в Директе

Без одобренной заявки боевой API часто отвечает отказом, даже если токен уже есть. Срок — **до 7 дней**.

1. Тот же логин **vitaminki21**.
2. Открой https://direct.yandex.ru/registered/main.pl?cmd=apiCertificationRequestList  
   (Директ → настройки → **Настройки API** → **Мои заявки**).
3. Первый заход: прими пользовательское соглашение.
4. **Новая заявка**.
5. В форме:
   - **ClientID** — тот, что из этапа 1 (выпадающий список).
   - Почта — рабочая, та же.
   - Название / описание честно, чтобы не отклонили, например:  
     «Собственное приложение. Один пользователь. Выгрузка статистики своих кампаний boat-sochi (vitaminki21) для анализа. Не публичный сервис, не агентство.»
   - Пользователей: **1**.
   - Соглашение — галка.
6. **Отправить**.
7. Статус смотри на той же странице: ожидает / одобрена / отклонена.  
   Если отклонили — прочитай причину, поправь заявку, отправь снова.

Пока заявка не одобрена, токен можно выпустить (этап 3), но скрипт к боевому API может не заработать.

---

## Этап 3. Выпустить токен в браузере

1. Всё ещё под **vitaminki21**.
2. Возьми ClientID (https://oauth.yandex.ru/ → твоё приложение).
3. В адресную строку вставь **одну** ссылку, подставив свой ClientID без пробелов:

```
https://oauth.yandex.ru/authorize?response_type=token&client_id=СЮДА_CLIENTID
```

4. Страница «Разрешить приложению … доступ». Нажми **Разрешить**.
5. Браузер уйдёт на адрес вида:

```
https://oauth.yandex.ru/verification_code#access_token=y0_XXXX&expires_in=31536000
```

6. Скопируй значение **после** `access_token=` и **до** `&expires_in`.  
   Обычно начинается с `y0_`. Это и есть токен.
7. `expires_in` — жизнь в секундах (часто около года). Когда истечёт — повтори этап 3.
8. Яндекс этот токен в кабинете больше не покажет. Сразу на этап 4.

Если в адресе `#error=...` — приложение заблокировано или неверный ClientID. Проверь этап 1.

Отозвать токен: https://oauth.yandex.ru/ → приложение → права / отозвать доступ. После отзыва агенты перестанут ходить в API.

## Этап 4. Секрет в Cursor (не в чат)

1. Открой https://cursor.com/dashboard/cloud-agents  
   (или https://cursor.com/dashboard?tab=cloud-agents).
2. Вкладка **Secrets** (секреты окружения / Cloud Agents).
3. **Add secret** / добавить:
   - Имя **точно:** `YANDEX_DIRECT_TOKEN`
   - Значение: токен `y0_...` (без кавычек, без пробелов, без `Bearer`).
4. По желанию второй секрет:  
   имя `YANDEX_DIRECT_LOGIN`  
   значение `vitaminki21`  
   (нужен, если кабинет агентский; для своего логина обычно достаточно токена).
5. Сохрани. В репозиторий и в `.cursor/environment.json` токен **не** клади.

Уже открытый чат агента секрет часто **не видит**. Нужен новый запуск агента после сохранения секрета.

## Этап 5. Напиши мне

В этот чат **без токена**:

```
Секреты лежат: YANDEX_DIRECT_TOKEN (и YANDEX_DIRECT_LOGIN если добавлял).
Заявка API в Директе: одобрена / ещё ждём.
Пиши клиент выгрузки.
```

Дальше появится скрипт: неделя Пн–Вс, номер РК (704503370, 713449981, …), запросы / группы / дни.

Пока заявки нет или секрета нет — агенты работают как раньше: CSV + скрины.

## Частые сбои

| Что видишь | Что делать |
|------------|------------|
| Чужой кабинет Директа | Не тот Яндекс в браузере. Инкогнито, только vitaminki21 |
| Нет пункта «Настройки API» | В кабинете должна быть хотя бы одна кампания; открой ссылку заявок из этапа 2 |
| Заявка «ожидает» | Жди до 7 дней, токен уже можно сохранить |
| Заявка отклонена | Прочитай причину, не пиши «универсальный бот для всех клиентов» |
| В URL `error=` | Неверный ClientID или приложение заблокировано |
| Скопировал Client secret | Это не токен. Нужен `access_token` из адресной строки |
| Агент говорит «нет токена» | Секрет добавлен после старта чата — открой нового агента |
| API ошибка 1002 | Битый / отозванный / чужой токен. Этап 3 заново |
| API «нет доступа к методу» | Заявка не одобрена или нет права `direct:api` |
