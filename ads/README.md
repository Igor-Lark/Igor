# Рекламные кампании (спецификации)

## Структура

- `ads/<клиент>/` — Markdown-спецификации, CSV для импорта, **Word (.docx)** для передачи в работу.
- Дубликаты для удобства: `cursor/<клиент>/`, `локальная/<клиент>/` (по запросу или по привычке репозитория).

## Word: обязательный формат

Любая новая или обновлённая рекламная кампания сопровождается **читаемым .docx**, не «сырым» копированием Markdown.

Генератор: [`scripts/md_spec_to_docx.py`](scripts/md_spec_to_docx.py)

```bash
python3 ads/scripts/md_spec_to_docx.py ads/<клиент>/my-campaign.md
python3 ads/scripts/md_spec_to_docx.py ads/<клиент>/my-campaign.md --ads ads/<клиент>/my-campaign-ads.csv
```

**Что получается в Word:**

- заголовок документа (стиль Title);
- строка «Клиент: …» под заголовком (из аргумента `--client` или из `*Клиент: …*` в конце md);
- разделы `##` → нумерованные заголовки «1. …», «2. …»;
- подразделы `###` → Heading 2;
- таблицы Markdown → таблицы Word с жирной шапкой;
- цитаты `>` → курсив с отступом;
- списки `-` и нумерованные шаги;
- блоки ``` → моноширинный текст (UTM и т.п.);
- опционально **приложение с объявлениями** из CSV (`--ads`), если в md нет полных таблиц по каждому объявлению.

Строки в md, начинающиеся с `**Word:**` или `**DOCX:**`, в Word **не попадают** (ссылку на файл даём в GitHub / в ответе пользователю).

## Markdown для кампаний

Рекомендуемая структура `.md`:

1. `#` — название кампании (один раз).
2. Краткое описание, блоки `>` для важных примечаний.
3. `##` — крупные разделы (настройки, гео, ключи, объявления, запуск).
4. Таблицы параметров, объявлений, быстрых ссылок — в Markdown-таблицах **или** в CSV + `--ads`.
5. В конце: `*Клиент: … · реквизиты*`.

После правок md **всегда пересобирать .docx** и коммитить md + docx (+ csv).
